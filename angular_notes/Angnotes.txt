1. INTERPOLATION (डेटा दिखाना HTML में)
================================================================================

⭐ KYA HAI YE?
Interpolation ka matlab hai - apne TypeScript ke variable ko HTML mein display karna.
Socho tumhare paas ek naam hai TypeScript mein, aur use HTML mein dikhana hai.
Bas double curly braces {{ }} ke andar variable ka naam likh do!

📝 SYNTAX:
{{variable_name}}

💡 REAL LIFE EXAMPLE:
Imagine karo Instagram ka profile page - jahan tumhara username dikhta hai.
Woh username backend se aata hai aur screen pe display hota hai. Same concept!

TypeScript (app.component.ts):
export class AppComponent {
  userName: string = 'Rahul_Sharma';
  followers: number = 1500;
  bio: string = 'Coding enthusiast | Delhi';
}

HTML (app.component.html):
<div class="profile">
  <h1>Welcome, {{userName}}! 🎉</h1>
  <p>Followers: {{followers}}</p>
  <p>Bio: {{bio}}</p>
</div>

OUTPUT:
Welcome, Rahul_Sharma! 🎉
Followers: 1500
Bio: Coding enthusiast | Delhi

⚠️ DHYAN RAKHNA:
- Interpolation HAMESHA string return karta hai (number bhi string ban jata hai)
- Variable naam exactly same hona chahiye TypeScript aur HTML mein
- Complex calculations bhi kar sakte ho: {{followers + 100}} → 1600 dikhega

🔥 PRO TIP:
Function call bhi kar sakte ho: {{getUserName()}}
Lekin zyada complex logic mat daalo, performance slow ho sakti hai!

================================================================================
2. PROPERTY BINDING (Properties ko Bind karna)
================================================================================

⭐ KYA HAI YE?
Property binding ka matlab hai - HTML element ki property ko TypeScript variable se connect karna.
Square brackets [ ] use karte hain iske liye.

📝 SYNTAX:
[property]='variable_name'

💡 REAL LIFE EXAMPLE:
Tumhe ek button disabled karna hai agar user logged in nahi hai.
Ya input field mein default value set karni hai.

TypeScript (app.component.ts):
export class AppComponent {
  userLoggedIn: boolean = false;
  defaultEmail: string = 'user@example.com';
  imageUrl: string = 'https://example.com/profile.jpg';
  inputDisabled: boolean = true;
}

HTML (app.component.html):
<!-- Button ko disable karna -->
<button [disabled]="!userLoggedIn">Submit Form</button>

<!-- Input mein default value -->
<input type="email" [value]="defaultEmail">

<!-- Image ka source set karna -->
<img [src]="imageUrl" alt="Profile Picture">

<!-- Input disable karna -->
<input type="text" [disabled]="inputDisabled" placeholder="Can't type here!">

🎯 INTERPOLATION vs PROPERTY BINDING - CONFUSION CLEAR KARTE HAIN!

SIMILARITY:
Dono se data TypeScript se HTML mein jata hai ✅

DIFFERENCE:
┌─────────────────────────────────────────────────────────────────┐
│ FEATURE          │ INTERPOLATION    │ PROPERTY BINDING          │
├──────────────────┼──────────────────┼───────────────────────────┤
│ Syntax           │ {{value}}        │ [property]="value"        │
│ Data Type        │ Always String    │ Original type preserved   │
│ Use Case         │ Display text     │ Set element properties    │
│ Example          │ <h1>{{name}}</h1>│ <img [src]="url">        │
└─────────────────────────────────────────────────────────────────┘

🔥 PRACTICAL DIFFERENCE:
TypeScript:
isActive: boolean = true;
count: number = 5;

❌ GALAT (Interpolation for boolean):
<button disabled="{{isActive}}">Click</button>
// Result: disabled="true" (string hai, hamesha disabled rahega!)

✅ SAHI (Property Binding):
<button [disabled]="isActive">Click</button>
// Result: Actually disabled/enabled hoga based on boolean value

🔥 PRO TIP:
- Text dikhane ke liye → Interpolation {{}}
- HTML attributes set karne ke liye → Property Binding []
- Boolean/Number properties ke liye HAMESHA Property Binding use karo!

3. EVENT BINDING (User Actions ko Handle karna)
================================================================================
⭐ KYA HAI YE?
Event binding ka matlab hai - user kuch action kare (click, hover, type) toh usko handle karna.
Jaise WhatsApp mein send button pe click karte ho, toh message send hota hai. That's event binding!

📝 SYNTAX:
(eventName)="functionName()"

💡 COMMON EVENTS (Sabse Zyada Use Hone Wale):

🖱️ MOUSE EVENTS:
┌────────────────────────────────────────────────────────────┐
│ Event          │ Kab Trigger Hota Hai                      │
├────────────────┼───────────────────────────────────────────┤
│ (click)        │ Single click - sabse common!             │
│ (dblclick)     │ Double click - zoom karne ke liye        │
│ (mouseover)    │ Mouse element pe aaya                    │
│ (mouseleave)   │ Mouse element se bahar gaya              │
│ (mousedown)    │ Mouse button dabaya (press kiya)        │
│ (mouseup)      │ Mouse button chhoda (release kiya)      │
│ (mouseenter)   │ Mouse element ke andar aaya              │
│ (mousemove)    │ Mouse move ho raha hai element pe        │
└────────────────────────────────────────────────────────────┘

⌨️ KEYBOARD EVENTS (Next section mein detail mein):
- (keypress) - Koi bhi key press karo
- (keydown) - Key press hui
- (keyup) - Key release hui

🎨 DRAG EVENTS:
- (drag) - Element ko drag kar rahe ho
- (dragover) - Dragged element kisi element ke upar hai

📱 TOUCH EVENTS (Mobile ke liye):
- (touchstart) - Screen touch hui
- (touchend) - Touch finish hui
- (touchmove) - Touch move ho raha

📊 DATA FLOW SAMAJHLO (BAHUT IMPORTANT!):

TypeScript ←→ HTML (Data Flow Direction):

1️⃣ INTERPOLATION {{}} & PROPERTY BINDING []:
   TypeScript → HTML (One way)
   Data TypeScript se HTML mein jata hai

2️⃣ EVENT BINDING ():
   HTML → TypeScript (One way)
   User ka action HTML se TypeScript mein jata hai

3️⃣ TWO-WAY BINDING [(ngModel)]:
   TypeScript ←→ HTML (Both ways)
   Dono taraf se data ja sakta hai (aage dekhenge)

🔥 PRO TIPS:
✅ Function name ke brackets () zaroor lagao
✅ Function ko quotes " " ke andar mat likho
✅ Multiple events ek element pe laga sakte ho
✅ Condition bhi likh sakte ho: (click)="count > 5 ? reset() : increment()"

❌ COMMON MISTAKES:
- (click)="myFunction" ❌ → Brackets bhul gaye!
- (click)="myFunction()" ✅ → Sahi hai!

⭐ KYA HAI YE?
Jab user keyboard pe kuch type kare, tab kya karna hai - ye define karna.

5. EVENT OBJECT ($event) - Event Ki Puri Jankari
================================================================================
⭐ KYA HAI YE?
$event ek special object hai jo event ke baare mein PURI information rakhta hai.
Jaise - kaunsi key press hui, mouse kahan tha, input ki value kya hai, etc.

Think of it like a package 📦 jisme event ki saari details hain!

📝 SYNTAX:
HTML mein $event pass karo:
<input (keyup)="myFunction($event)">

TypeScript mein receive karo:
myFunction(event: any) {
  // Ab event object use kar sakte ho
}

💡 $EVENT SE KYA KYA MIL SAKTA HAI?

┌─────────────────────────────────────────────────────────────────┐
│ Property/Method     │ Kya Milta Hai                             │
├─────────────────────┼───────────────────────────────────────────┤
│ event.target        │ Jis element pe event hua (input, button) │
│ event.target.value  │ Input field ki current value              │
│ event.target.checked│ Checkbox checked hai ya nahi (boolean)    │
│ event.key           │ Konsi key press hui (Enter, Escape, etc) │
│ event.keyCode       │ Key ka code number (13 for Enter)        │
│ event.type          │ Event ka type (click, keyup, etc)        │
│ event.clientX       │ Mouse ka X position (screen pe)          │
│ event.clientY       │ Mouse ka Y position (screen pe)          │
│ event.ctrlKey       │ Ctrl key dabai thi? (true/false)         │
│ event.shiftKey      │ Shift key dabai thi? (true/false)        │
│ event.preventDefault()│ Browser ka default action rokna         │
│ event.stopPropagation()│ Event ko parent tak mat jane dena     │
└─────────────────────────────────────────────────────────────────┘

EXAMPLE 5: Keyboard Shortcuts (Ctrl+S, Ctrl+P, etc)
TypeScript:
export class AppComponent {
  onKeyboardShortcut(event: KeyboardEvent) {
    // Ctrl + S (Save)
    if (event.ctrlKey && event.key === 's') {
      event.preventDefault(); // Browser ka save dialog mat kholo
      this.saveData();
    }
    
    // Ctrl + P (Print)
    if (event.ctrlKey && event.key === 'p') {
      event.preventDefault();
      this.printPage();
    }
    
    // Escape (Close modal)
    if (event.key === 'Escape') {
      this.closeModal();
    }
  }
  
  saveData() {
    console.log('Data saved! 💾');
  }
  
  printPage() {
    console.log('Print initiated! 🖨️');
  }
  
  closeModal() {
    console.log('Modal closed! ❌');
  }
}

HTML:
<div (keydown)="onKeyboardShortcut($event)" tabindex="0">
  <p>Try pressing Ctrl+S, Ctrl+P, or Escape</p>
</div>

🎯 COMMON USE CASES (Real Projects Mein):

1️⃣ INPUT FIELD VALUES: event.target.value
2️⃣ FORM SUBMIT ROKNA: event.preventDefault()
3️⃣ CHECKBOX STATUS: event.target.checked
4️⃣ KEYBOARD SHORTCUTS: event.ctrlKey, event.key
5️⃣ MOUSE TRACKING: event.clientX, event.clientY
6️⃣ EVENT BUBBLING: event.stopPropagation()

🔥 PRO TIPS:
✅ $event HTML mein likhna zaroori hai explicitly
✅ TypeScript mein type dena best practice: (event: any) ya (event: Event)
✅ Specific types use karo: MouseEvent, KeyboardEvent, etc
✅ preventDefault() form submissions ke liye must hai

❌ COMMON MISTAKES:
- $event ko quotes mein mat likho: ($event) ✅, ("$event") ❌
- event parameter bhul gaye function mein
- event.target ka type check karna bhul gaye

6. TWO-WAY BINDING [(ngModel)] - Dono Taraf Se Data Flow
================================================================================
⭐ KYA HAI YE?
Two-way binding ka matlab hai - data dono taraf se ja sakta hai!
TypeScript se HTML mein BHI, aur HTML se TypeScript mein BHI! 🔄

Yani agar user input field mein type kare, toh automatically variable update ho jaye.
Aur agar TypeScript mein variable change karo, toh HTML mein bhi dikhe!

📝 SYNTAX:
[(ngModel)]="variable_name"

🎯 BANANA IN A BOX! 🍌📦
Yaad rakhne ka easy tarika:
- [( )] → Looks like a banana in a box!
- [ ] = Property binding (TypeScript → HTML)
- ( ) = Event binding (HTML → TypeScript)
- [( )] = Dono combine = Two-way binding!

⚙️ SETUP KAISE KAREN? (IMPORTANT!)

Step 1: FormsModule import karo

TypeScript (app.component.ts):
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms'; // ← Ye import karo

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [FormsModule], // ← Yahan add karo
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css']
})
export class AppComponent {
  userName: string = '';
}

🎯 TWO-WAY BINDING vs ONE-WAY BINDING:

WITHOUT TWO-WAY BINDING (Zyada Code):
<input 
  [value]="userName" 
  (input)="userName = $event.target.value">

WITH TWO-WAY BINDING (Clean Code):
<input [(ngModel)]="userName">

Dono same kaam karte hain, but [(ngModel)] cleaner hai! ✨

⚠️ DISADVANTAGES (Jaanna Zaroori Hai):

1️⃣ TIGHT COUPLING:
View aur data directly connected ho jate hain.
Large apps mein manage karna mushkil ho sakta hai.

2️⃣ PERFORMANCE ISSUES:
Bahut sare [(ngModel)] bindings slow kar sakte hain app ko.
Especially large forms (100+ fields) mein.

3️⃣ DEBUGGING DIFFICULT:
Data kahan se change ho raha hai ye track karna mushkil.

✅ BETTER ALTERNATIVES (Modern Angular):

1️⃣ REACTIVE FORMS (Professional Projects Mein):
More control, better validation, easier testing.

2️⃣ SIGNALS (Angular 16+):
New feature - better performance aur reactivity.

TypeScript:
import { signal } from '@angular/core';

export class AppComponent {
  userName = signal(''); // Signal create kiya
  
  updateName(newName: string) {
    this.userName.set(newName); // Update karo
  }
}

HTML:
<input 
  [value]="userName()" 
  (input)="updateName($event.target.value)">
<p>Hello, {{userName()}}!</p>

🔥 PRO TIPS:
✅ Small forms ke liye [(ngModel)] perfect hai
✅ FormsModule import karna mat bhulna
✅ Large forms ke liye Reactive Forms use karo
✅ Name attribute dena optional hai ngModel ke saath

❌ COMMON ERRORS:
Error: "Can't bind to 'ngModel'"
Fix: FormsModule import karna bhul gaye!

Error: "NgModel used without name attribute"
Fix: name="fieldName" add karo (forms mein)

🎓 SUMMARY:
- [(ngModel)] = Two-way data binding
- FormsModule zaroori hai
- Small forms ke liye best
- Large apps → Reactive Forms use karo

7. DIRECTIVES - HTML Ko Superpowers Dena 🦸
================================================================================
⭐ KYA HAIN YE?
Directives are like special instructions jo HTML elements ko extra powers dete hain! 🎯
Regular HTML mein sirf basic tags hote hain (div, p, button).
Directives se tum conditionally hide/show, loop, styling - sab kar sakte ho!

Soch lo ke ye HTML ke liye superpowers hain jaise superhero ko milti hain! 🦸‍♂️

📝 THREE TYPES OF DIRECTIVES:

1️⃣ STRUCTURAL DIRECTIVES (DOM Ko Change Karte Hain):
   - Elements ko add/remove karte hain DOM se
   - Star * symbol se start hote hain
   - Examples: *ngIf, *ngFor, *ngSwitch
   - Think: Building blocks add/remove kar rahe ho

2️⃣ ATTRIBUTE DIRECTIVES (Appearance/Behavior Change Karte Hain):
   - Existing elements ki styling ya behavior change karte hain
   - DOM mein elements add/remove NAHI karte
   - Examples: ngClass, ngStyle, ngModel
   - Think: Elements ko paint kar rahe ho ya properties change kar rahe

3️⃣ COMPONENT DIRECTIVES (Components Render Karte Hain):
   - Poore component ko render karte hain template mein
   - Apne khud ke components bhi directives hain technically!
   - Example: <app-header>, <app-footer>

┌────────────────────────────────────────────────────────────────┐
│ Type         │ Symbol │ DOM Change? │ Examples                 │
├──────────────┼────────┼─────────────┼──────────────────────────┤
│ Structural   │ *      │ Yes ✅      │ *ngIf, *ngFor, *ngSwitch│
│ Attribute    │ None   │ No ❌       │ ngClass, ngStyle        │
│ Component    │ None   │ Yes ✅      │ <app-header>            │
└────────────────────────────────────────────────────────────────┘

🎯 STRUCTURAL vs ATTRIBUTE - Confusion Clear Karte Hain:

STRUCTURAL DIRECTIVE (*ngIf):
<div *ngIf="showElement">
  <!-- Agar condition false → Pura div DOM se remove! -->
  Ye dikhega ya nahi, depends on condition
</div>

ATTRIBUTE DIRECTIVE (ngClass):
<div [ngClass]="{'hidden': !showElement}">
  <!-- Element DOM mein rehta hai, sirf CSS change hoti hai -->
  Ye hamesha DOM mein hai, bas class change hoti
</div>

Real Life Analogy:
- Structural = Ghar mein kamra add/remove karna 🏗️
- Attribute = Kamre ka color/furniture change karna 🎨

🔥 QUICK REFERENCE:

STRUCTURAL (Sabse Common):
- *ngIf → Show/hide based on condition
- *ngFor → Loop through array
- *ngSwitch → Switch case logic

ATTRIBUTE (Sabse Common):
- ngClass → Dynamic CSS classes
- ngStyle → Dynamic inline styles
- ngModel → Two-way binding

💡 Important Rule:
Ek element pe SIRF EK structural directive laga sakte ho!

❌ GALAT:
<div *ngIf="condition" *ngFor="let item of items">
  <!-- Error! Ek element pe 2 structural directives nahi -->
</div>

✅ SAHI:
<div *ngIf="condition">
  <div *ngFor="let item of items">
    <!-- Nested use karo, separate elements pe -->
  </div>
</div>

Ya use <ng-container>:
<ng-container *ngIf="condition">
  <div *ngFor="let item of items">
    <!-- ng-container DOM mein nahi aata, clean solution -->
  </div>
</ng-container>

8. *ngIf DIRECTIVE - Show/Hide Karna Like a Boss! 👁️
================================================================================
⭐ KYA HAI YE?
*ngIf ka matlab hai - agar condition TRUE hai toh element SHOW karo, warna DOM se hata do!
Ye conditional rendering kehte hain - jaise Instagram pe posts dikhte/chhupte hain! 📱

📝 SYNTAX:
<element *ngIf="condition">Content</element>

💡 REAL LIFE EXAMPLES:

EXAMPLE 1: Login Button (Basic)
TypeScript:
export class AppComponent {

EXAMPLE 3: Error Messages (Forms Mein)

🎯 *ngIf vs CSS display:none - BAHUT IMPORTANT!

┌──────────────────────────────────────────────────────────────┐
│ Feature        │ *ngIf           │ CSS display:none        │
├────────────────┼─────────────────┼─────────────────────────┤
│ DOM mein hai?  │ NO ❌ (removed) │ YES ✅ (hidden)         │
│ Performance    │ Better ✅       │ Worse ❌                │
│ Memory         │ Less used ✅    │ More used ❌            │
│ Re-initialize  │ Yes (on show)   │ No                      │
└──────────────────────────────────────────────────────────────┘

CSS APPROACH (Not Recommended):
<div [style.display]="showElement ? 'block' : 'none'">
  <!-- DOM mein rahega, sirf chhupega -->
  This stays in DOM even when hidden
</div>

*ngIf APPROACH (Recommended ✅):
<div *ngIf="showElement">
  <!-- DOM se completely remove ho jayega -->
  This is removed from DOM when false
</div>

WHY *ngIf BETTER?
✅ Less memory use (element DOM mein nahi)
✅ Better performance (browser ko render nahi karna)
✅ Secure (hidden data really hidden hai)

WHEN TO USE CSS:
- Animations chahiye (fade in/out)
- Frequently toggle hota hai (har second)

💡 STORING VALUE IN LOCAL VARIABLE (Advanced):

TypeScript:
export class AppComponent {

    return {
      name: 'Rahul',
      age: 24,
      city: 'Delhi'
    };
  }
}

HTML (Without Storing):

  <p>Name: {{getUserData().name}}</p>
  <p>Age: {{getUserData().age}}</p>
  <p>City: {{getUserData().city}}</p>
  <!-- Function 3 baar call hua! Performance issue! ❌ -->
</div>

HTML (With Storing - Better! ✅):
<div *ngIf="getUserData() as user">
  <p>Name: {{user.name}}</p>
  <p>Age: {{user.age}}</p>
  <p>City: {{user.city}}</p>
  <!-- Function sirf 1 baar call hua! ✅ -->
</div>

⚠️ IMPORTANT:
'as' keyword se banaya hua variable SIRF us *ngIf block ke andar kaam karega!
Bahar use nahi kar sakte.

🔥 PRO TIPS:
✅ Simple conditions ke liye *ngIf perfect hai
✅ Performance ke liye CSS display se better
✅ else block ke liye ng-template use karo (aage dekhenge)
✅ Complex logic function mein likho, HTML mein nahi

❌ AVOID:
<div *ngIf="age > 18 && age < 65 && hasLicense && !isSuspended && city === 'Delhi'">
  <!-- Itna complex logic HTML mein mat likho! -->
</div>

✅ BETTER:
TypeScript:
get canDrive(): boolean {
  return this.age > 18 && this.age < 65 && 
         this.hasLicense && !this.isSuspended && 
         this.city === 'Delhi';
}

HTML:
<div *ngIf="canDrive">
  <!-- Clean aur readable! ✅ -->
</div>

9. @if and @else - MODERN WAY (Angular 17+) 🚀
================================================================================

⭐ KYA HAI YE?
@if Angular ka NAYA syntax hai (version 17 ke baad)!
Purana *ngIf bhi kaam karta hai, but @if zyada fast aur clean hai! ⚡

Why New Syntax?
- Better performance (faster rendering)
- Cleaner code (easier to read)
- Built-in else support (ng-template ki zaroorat nahi)

📝 SYNTAX:
@if (condition) {
  <!-- True hone pe ye dikhe -->
} @else {
  <!-- False hone pe ye dikhe -->
}

💡 REAL LIFE EXAMPLES:

EXAMPLE 1: Login Status
TypeScript:
export class AppComponent {
  isLoggedIn: boolean = false;
  userName: string = 'Rahul';
  
  toggleLogin() {
    this.isLoggedIn = !this.isLoggedIn;
  }
}

HTML:
<button (click)="toggleLogin()">Toggle Login</button>

@if (isLoggedIn) {
  <div class="welcome">
    <h2>Welcome back, {{userName}}! 🎉</h2>
    <p>You are logged in</p>
  </div>
} @else {
  <div class="login-prompt">
    <h2>Please Login 🔐</h2>
    <button>Login</button>
  </div>
}

EXAMPLE 2: Data Loading States
TypeScript:
export class AppComponent {
  dataState: 'loading' | 'success' | 'error' = 'loading';
  data: any[] = [];
  
  loadData() {
    this.dataState = 'loading';
    // Simulate API call
    setTimeout(() => {
      // this.dataState = 'success';  // Success case
      this.dataState = 'error';  // Error case
    }, 2000);
  }
}

HTML:
@if (dataState === 'loading') {
  <div class="loader">Loading data... ⏳</div>
} @else if (dataState === 'success') {
  <div class="success">Data loaded! ✅</div>
} @else {
  <div class="error">Failed to load data ❌</div>
}

EXAMPLE 3: Nested Conditions (Real App Scenario)
TypeScript:

  userRole: 'admin' | 'user' | 'guest' = 'user';
  isPremium: boolean = true;
}

HTML:

  <div class="admin-panel">
    <h2>Admin Dashboard 👑</h2>
    <button>Manage Users</button>
    <button>View Analytics</button>
  </div>
} @else if (userRole === 'user') {
  @if (isPremium) {
    <div class="premium-user">
      <h2>Premium User ⭐</h2>
      <p>Enjoy all features!</p>
    </div>
  } @else {
    <div class="regular-user">

  <div class="guest">

    <button>Sign Up</button>
  </div>

🎯 *ngIf vs @if - COMPARISON:

OLD WAY (*ngIf):
<div *ngIf="condition; else elseBlock">
  Content when true
</div>
<ng-template #elseBlock>
  Content when false
</ng-template>
<!-- Template reference lagana padta tha 😕 -->

NEW WAY (@if) - CLEANER! ✅:
@if (condition) {
  Content when true
} @else {
  Content when false
}
<!-- Simple aur readable! 😊 -->

┌─────────────────────────────────────────────────────────────┐
│ Feature         │ *ngIf (Old)    │ @if (New)               │
├─────────────────┼────────────────┼─────────────────────────┤
│ Syntax          │ *ngIf="x"      │ @if(x) {}               │
│ Else support    │ ng-template    │ Built-in @else          │
│ Readability     │ Medium         │ Better ✅               │
│ Performance     │ Good           │ Better ✅               │
│ Angular version │ All versions   │ 17+ only                │
└─────────────────────────────────────────────────────────────┘

🔥 PRO TIPS:
✅ Angular 17+ projects mein @if use karo
✅ Purane projects mein *ngIf bhi theek hai
✅ @else if for multiple conditions
✅ Curly braces {} zaroor lagao

⚠️ MIGRATION:
Angular automatically *ngIf ko @if mein convert kar sakta hai!
Command: ng generate @angular/core:control-flow

❌ COMMON MISTAKES:
@if condition {  // ❌ Brackets bhul gaye
@if (condition) // ❌ Curly braces bhul gaye
@if (condition) { } // ✅ Correct!

💡 WHEN TO USE:
- New projects → @if (recommended)
- Old projects → *ngIf (or migrate)
- Learning → Dono sikh lo, both are useful!

⚡ PERFORMANCE OPTIMIZATION - trackBy Function

⚠️ PROBLEM:
By default, agar array mein koi change aaye (add/delete/update), 
toh Angular POORI list ko re-render karta hai! 🐢
Isse performance slow ho jati hai large lists mein (1000+ items).

✅ SOLUTION: trackBy Function
Ye Angular ko batata hai ki "kis unique property se items ko identify karo"

EXAMPLE 6: trackBy Implementation
TypeScript:
export class AppComponent {
  employees = [
    { id: 1, name: 'Rahul', salary: 50000 },
    { id: 2, name: 'Priya', salary: 60000 },
    { id: 3, name: 'Amit', salary: 55000 }
  ];
  
  // trackBy function - Angular ko batayega ki ID se track karo
  trackByEmployeeId(index: number, employee: any): number {
    return employee.id;  // Unique identifier
  }
  
  addEmployee() {
    this.employees.push({ 
      id: 4, 
      name: 'Neha', 
      salary: 65000 
    });
    // Sirf NAYA item render hoga, purane items nahi! ✅
  }
  
  updateSalary() {
    this.employees[0].salary = 55000;
    // Sirf UPDATED item render hoga! ✅
  }
}

HTML (WITHOUT trackBy - SLOW 🐢):
<tr *ngFor=\"let emp of employees\">
  <td>{{emp.name}}</td>
  <td>{{emp.salary}}</td>
</tr>
<!-- Har change pe SARE items re-render honge! -->

HTML (WITH trackBy - FAST ⚡):
<tr *ngFor=\"let emp of employees; trackBy: trackByEmployeeId\">
  <td>{{emp.name}}</td>
  <td>{{emp.salary}}</td>
</tr>
<!-- Sirf changed items render honge! -->

HOW trackBy WORKS:
1. Angular har item ki ID check karta hai
2. Agar ID same hai → Reuse existing element
3. Agar ID new hai → Create new element
4. Agar ID missing → Remove element

================================================================================

⭐ KYA HAI YE?
@for Angular ka NAYA syntax hai for loops ke liye! (Version 17+)
Purana *ngFor bhi kaam karta hai, but @for mein built-in @empty state hai! 🎯

Matlab agar array khali ho, toh automatically "No data found" type message dikha sakte ho!

📝 SYNTAX:
@for (item of arrayName; track item.id) {
  <!-- Items yahan dikhenge -->
} @empty {
  <!-- Array khali ho toh ye dikhega -->
}

⚠️ IMPORTANT: 'track' keyword MANDATORY hai @for mein!
Performance ke liye zaroori - konse item ko track karna hai ye batata hai.

🎯 *ngFor vs @for - COMPARISON:

┌───────────────────────────────────────────────────────────────────┐
│ Feature        │ *ngFor (Old)      │ @for (New)                  │
├────────────────┼───────────────────┼─────────────────────────────┤
│ Syntax         │ *ngFor=\"let x\"  │ @for(x; track x.id) {}      │
│ Empty state    │ Manual with *ngIf │ Built-in @empty ✅          │
│ Track          │ Optional          │ MANDATORY ⚠️                │
│ Performance    │ Good              │ Better ⚡                   │
│ Readability    │ Medium            │ Better ✅                   │
│ Version        │ All               │ Angular 17+ only            │
└───────────────────────────────────────────────────────────────────┘

OLD WAY (*ngFor with empty check):
<div *ngIf=\"items.length > 0; else noItems\">
  <div *ngFor=\"let item of items\">{{item}}</div>
</div>
<ng-template #noItems>
  <p>No items!</p>
</ng-template>
<!-- Bahut zyada code! 😫 -->

NEW WAY (@for):
@for (item of items; track item.id) {
  <div>{{item}}</div>
} @empty {
  <p>No items!</p>
}
<!-- Clean aur simple! 😊 -->

🔥 PRO TIPS:

✅ track ALWAYS use karo - unique ID best hai (like emp.id)
✅ @empty state BAHUT useful hai empty states ke liye
✅ $index, $first, $last styling ke liye perfect
✅ Nested @for bhi kar sakte ho (arrays ke andar arrays)
✅ Performance *ngFor se better hai

❌ COMMON MISTAKES:

1. track bhul gaye:
   @for (item of items) { }  ❌ Error!
   @for (item of items; track item.id) { }  ✅

2. Variable access galat:
   @for (item of items; track item.id; index as i) { }  ❌
   @for (item of items; track item.id; let i = $index) { }  ✅

3. Curly braces bhul gaye:
   @for (item of items; track item.id)  ❌
   @for (item of items; track item.id) { }  ✅

4. @empty optional hai - zaruri nahi:
   @for (item of items; track item.id) {
     <!-- Just items -->
   }
   <!-- @empty nahi lagaya - no problem! -->

⚠️ IMPORTANT NOTES:

📌 track ka Purpose:
Angular ko batata hai ki konse item ko kaise identify kare.
Best practice: Unique ID use karo (database ID, UUID, etc.)

📌 Migration:
Purane *ngFor ko @for mein convert kar sakte ho:
Command: ng generate @angular/core:control-flow

📌 When to Use:
- New projects → @for (recommended)
- Old projects → *ngFor (or migrate)
- Need empty state → @for is PERFECT ✅

🎓 SUMMARY:
- @for = Modern loop syntax

🎯 *ngSwitch vs Multiple *ngIf - COMPARISON:

USING MULTIPLE *ngIf (Not Recommended ❌):

<!-- Sirf matching case check hoga, efficient! -->

⚠️ IMPORTANT RULES:

1️⃣ ONE SWITCH CONTAINER:
[ngSwitch] sirf parent element pe lagta hai

❌ Same value ke 2 cases nahi ho sakte:
<div *ngSwitchCase="'admin'">Admin 1</div>

3️⃣ ONE DEFAULT ONLY:
❌ Multiple *ngSwitchDefault nahi ho sakte:
<div *ngSwitchDefault>Default 1</div>
<div *ngSwitchDefault>Default 2</div>  <!-- Error! -->

4️⃣ STRING VALUES:
Strings ko quotes mein likhna ZAROORI:
<div *ngSwitchCase="'admin'">  ✅ Correct
<div *ngSwitchCase="admin">    ❌ Wrong (variable samjhega)

5️⃣ NUMBER VALUES:
Numbers ko quotes ke bina:
<div *ngSwitchCase="10">  ✅ Correct
<div *ngSwitchCase="'10'">  ❌ Wrong (string ban jayega)

🔥 PRO TIPS:

✅ 3+ conditions ho toh *ngSwitch use karo
✅ 1-2 conditions ho toh *ngIf better hai
✅ Default case hamesha add karo (error handling ke liye)
✅ String values ko quotes mein wrap karo
✅ Complex logic function mein likho

❌ COMMON MISTAKES:

1. Quotes bhul gaye string mein:
   <div *ngSwitchCase="admin">  ❌ (variable ban jayega)

   <div *ngSwitchDefault>One</div>

   TypeScript: age: number = 25

📌 WHEN TO USE:

✅ USE *ngSwitch WHEN:
- Multiple fixed options (3+)
- Value-based rendering
- Status/state displays

- Payment methods
- Subscription tiers

❌ DON'T USE *ngSwitch WHEN:
- Simple true/false → Use *ngIf
- Range checks (age > 18) → Use *ngIf
- Complex conditions → Use *ngIf
- Just 2 options → Use *ngIf with else

🎯 *ngSwitch vs @switch - COMPARISON:

┌────────────────────────────────────────────────────────────────────┐
│ Feature        │ *ngSwitch (Old)     │ @switch (New)              │
├────────────────┼─────────────────────┼────────────────────────────┤
│ Syntax         │ [ngSwitch]=" "      │ @switch ( ) { }            │
│ Case syntax    │ *ngSwitchCase=" "   │ @case ( ) { }              │
│ Default syntax │ *ngSwitchDefault    │ @default { }               │
│ Readability    │ Medium              │ Better ✅                  │
│ Performance    │ Good                │ Better ⚡                  │
│ Code length    │ More verbose        │ Cleaner ✅                 │
│ Version        │ All versions        │ Angular 17+ only           │
└────────────────────────────────────────────────────────────────────┘

OLD WAY (*ngSwitch):
<div [ngSwitch]="status">
  <div *ngSwitchCase="'pending'">Pending</div>
  <div *ngSwitchCase="'done'">Done</div>
  <div *ngSwitchDefault>Unknown</div>
</div>
<!-- Parent div zaroori, quotes confusing -->

NEW WAY (@switch):
@switch (status) {
  @case ('pending') {
    <div>Pending</div>
  }
  @case ('done') {
    <div>Done</div>
  }
  @default {
    <div>Unknown</div>
  }
}
<!-- Cleaner, readable, no parent div needed! -->

🔥 PRO TIPS:

✅ Angular 17+ projects mein @switch prefer karo
✅ @default hamesha include karo (edge cases ke liye)
✅ Curly braces {} mandatory hain har case mein
✅ Parentheses () value ke liye mandatory
✅ Multiple statements ek case mein likh sakte ho

❌ COMMON MISTAKES:

1. Curly braces bhul gaye:
   @case ('value')  ❌ (braces missing)
   @case ('value') { }  ✅

2. Parentheses galat:
   @switch status { }  ❌
   @switch (status) { }  ✅

3. @default missing:
   <!-- Hamesha @default add karo unexpected values ke liye -->

4. Multiple @default:
   @default { }
   @default { }  ❌ Error!

📌 WHEN TO USE:

✅ USE @switch WHEN:
- Angular 17+ project ho
- Multiple fixed values (3+)
- Cleaner code chahiye
- Better performance chahiye

❌ USE *ngSwitch WHEN:
- Purana Angular version (<17)
- Legacy code maintain kar rahe ho

⚡ PERFORMANCE NOTE:
Control flow statements (@if, @for, @switch) faster hain than
their directive equivalents (*ngIf, *ngFor, *ngSwitch)!

Why? Kyunki ye directly JavaScript control flow use karte hain,
Angular ke directive overhead nahi hai!

14. ATTRIBUTE DIRECTIVES - Dynamic Styling Ka Jadoo! 🎨✨
================================================================================

⭐ KYA HAIN YE?
Attribute directives ka kaam hai - elements ki APPEARANCE aur BEHAVIOR ko dynamically change karna!
Matlab CSS classes aur styles ko TypeScript se control karna. 🎯

Structural directives (ngIf, ngFor) DOM mein elements add/remove karte hain,
but Attribute directives existing elements ko modify karte hain!

Real Life Example: Instagram pe dark mode toggle - click karte hi poora UI ka color change! 🌓

📝 MAIN ATTRIBUTE DIRECTIVES:
1. ngClass - Dynamic CSS classes apply karo
2. ngStyle - Dynamic inline styles apply karo

================================================================================
A) ngClass - CSS Classes Ko Dynamically Control Karo! 🎨
================================================================================

⭐ KYA HAI YE?
ngClass se tum CSS classes ko conditionally apply/remove kar sakte ho!
Jaise button click pe color change, hover pe effect, active state dikhaana - sab ngClass se!

📝 SYNTAX (4 Different Ways):

1️⃣ STRING (Single class):
<div [ngClass]="'className'">Content</div>

2️⃣ VARIABLE (Class name from TypeScript):
<div [ngClass]="myClass">Content</div>

3️⃣ ARRAY (Multiple classes):
<div [ngClass]="['class1', 'class2', 'class3']">Content</div>

4️⃣ OBJECT (Conditional classes - Most Common! ⭐):
<div [ngClass]="{'className': condition}">Content</div>

│ Pre-defined styles        │ ngClass ✅ (Better performance)         │
│ Multiple properties       │ ngClass ✅ (Cleaner code)               │
│ Reusable styles           │ ngClass ✅ (CSS classes)                │
│ Dynamic values            │ ngStyle ✅ (e.g., width: 50%)          │
│ Calculated properties     │ ngStyle ✅ (e.g., color from function)  │
│ User customizations       │ ngStyle ✅ (color picker, sliders)      │
└─────────────────────────────────────────────────────────────────────┘

🔥 PRO TIPS:

✅ ngClass for most cases (better performance)
✅ ngStyle for truly dynamic values (width%, colors, positions)
✅ Combine both if needed on same element
✅ Keep style logic in TypeScript, not template
✅ Use CSS variables for theme management

❌ COMMON MISTAKES:

1. CSS property names wrong:
   [ngStyle]=\"{'font-size': '16px'}\"  ✅ (kebab-case)
   [ngStyle]=\"{'fontSize': '16px'}\"   ✅ (camelCase)
   [ngStyle]=\"{'FontSize': '16px'}\"   ❌ (Wrong case)

2. Missing units:
   [ngStyle]=\"{'width': 100}\"     ❌ (No unit)
   [ngStyle]=\"{'width': '100px'}\" ✅ (With unit)

3. Object structure wrong:
   [ngStyle]=\"'color: red'\"               ❌
   [ngStyle]=\"{'color': 'red'}\"           ✅

4. Multiple styles as string:
   [ngStyle]=\"'color: red; font-size: 20px'\"  ❌
   [ngStyle]=\"{'color': 'red', 'font-size': '20px'}\"  ✅

================================================================================

18. COMPONENT LIFECYCLE HOOKS - Component Ki Zindagi! 🔄👶➡️💀
================================================================================

⭐ KYA HAIN YE?
Lifecycle hooks wo special methods hain jo component ki life ke DIFFERENT STAGES pe automatically run hote hain!

Real Life Analogy: Human life jaisa - Birth → Growth → Adult → Old → Death
Component bhi aisa hi: Create → Initialize → Update → Destroy 🌱➡️🌳➡️🍂

Har stage pe kuch special kaam kar sakte ho - data fetch karo, cleanup karo, changes track karo!

📊 COMPLETE LIFECYCLE ORDER (Sequence Yaad Rakho!):

1️⃣ constructor()           ← Class banta hai
2️⃣ ngOnChanges()          ← @Input() changes (can run multiple times)
3️⃣ ngOnInit()             ← Component ready (runs ONCE)
4️⃣ ngDoCheck()            ← Custom change detection
5️⃣ ngAfterContentInit()   ← Content projection ready (ONCE)
6️⃣ ngAfterContentChecked()← Content checked
7️⃣ ngAfterViewInit()      ← View ready (ONCE)
8️⃣ ngAfterViewChecked()   ← View checked
9️⃣ ngOnDestroy()          ← Component destroy hone se pehle (ONCE)

┌─────────────────────────────────────────────────────────────────────┐
│ Hook                  │ Runs     │ Use For                          │
├───────────────────────┼──────────┼──────────────────────────────────┤
│ constructor()         │ Once     │ Dependency injection             │
│ ngOnChanges()         │ Multiple │ Track @Input() changes           │
│ ngOnInit()            │ Once     │ API calls, initialization        │
│ ngDoCheck()           │ Multiple │ Custom change detection          │
│ ngAfterContentInit()  │ Once     │ Content projection ready         │
│ ngAfterContentChecked()│ Multiple│ After content checked            │
│ ngAfterViewInit()     │ Once     │ DOM ready, ViewChild access      │
│ ngAfterViewChecked()  │ Multiple │ After view checked               │
│ ngOnDestroy()         │ Once     │ Cleanup, unsubscribe             │
└─────────────────────────────────────────────────────────────────────┘

================================================================================
A) ngOnChanges() - @Input() Changes Track Karo! 🔄
================================================================================

⭐ KAB RUN HOTA HAI?
Jab bhi @Input() property change hoti hai, tab ye automatically trigger hota hai!
Parent se data aaya → ngOnChanges() chala!

📝 IMPORTANT:
- Pehli baar ngOnInit() se PEHLE run hota hai
- Har @Input() change pe run hota hai
- SimpleChanges object milta hai (previous aur current value)

💡 REAL LIFE EXAMPLE 1: User Profile Update Tracker

PARENT COMPONENT (app.component.ts):
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `
    <div class="parent">
      <h2>Parent Component - User Editor 👨‍💼</h2>
      
      <input [(ngModel)]="userName" placeholder="Enter name">
      <input type="number" [(ngModel)]="userAge" placeholder="Enter age">
      
      <button (click)="updateUser()">Update User Info</button>
      
      <hr>
      <app-user-profile 
        [userName]="userName" 
        [userAge]="userAge">
      </app-user-profile>
    </div>
  `
})
export class AppComponent {
  userName: string = 'Rahul Sharma';
  userAge: number = 24;
  
  updateUser() {
    console.log('User updated in parent!');
  }
}

CHILD COMPONENT (user-profile.component.ts):
import { Component, Input, OnChanges, SimpleChanges } from '@angular/core';

@Component({
  selector: 'app-user-profile',
  template: `
    <div class="child">
      <h3>Child Component - Profile Display 👤</h3>
      <p>Name: {{userName}}</p>
      <p>Age: {{userAge}}</p>
      
      <div class="change-log">
        <h4>Change History 📜</h4>
        <div *ngFor="let log of changeLogs">
          {{log}}
        </div>
      </div>
    </div>
  `
})
export class UserProfileComponent implements OnChanges {
  @Input() userName: string = '';
  @Input() userAge: number = 0;
  
  changeLogs: string[] = [];
  
  ngOnChanges(changes: SimpleChanges) {
    console.log('🔄 ngOnChanges called!');
    console.log('All changes:', changes);
    
    // Check which property changed
    if (changes['userName']) {
      const nameChange = changes['userName'];
      const log = `Name changed: "${nameChange.previousValue}" → "${nameChange.currentValue}"`;
      this.changeLogs.push(log);
      console.log('👤 Name change detected:', nameChange);
    }
    
    if (changes['userAge']) {
      const ageChange = changes['userAge'];
      const log = `Age changed: ${ageChange.previousValue} → ${ageChange.currentValue}`;
      this.changeLogs.push(log);
      console.log('🎂 Age change detected:', ageChange);
    }
  }
}

OUTPUT (Console):
// Jab userName "Rahul" se "Amit" hota hai:
🔄 ngOnChanges called!
👤 Name change detected: {previousValue: "Rahul Sharma", currentValue: "Amit Kumar", firstChange: false}

💡 EXAMPLE 2: SimpleChanges Object Ko Detail Mein Samajhna

TypeScript:
export class ProductComponent implements OnChanges {
  @Input() productName: string = '';
  @Input() productPrice: number = 0;
  @Input() inStock: boolean = true;
  
  ngOnChanges(changes: SimpleChanges) {
    // SimpleChanges object structure:
    // {
    //   'propertyName': {
    //     previousValue: old value,
    //     currentValue: new value,
    //     firstChange: boolean (true if first time)
    //   }
    // }
    
    for (const propName in changes) {
      const change = changes[propName];
      
      console.log(`Property: ${propName}`);
      console.log(`Previous: ${change.previousValue}`);
      console.log(`Current: ${change.currentValue}`);
      console.log(`First Change: ${change.firstChange}`);
      
      // Pehli baar change hai?
      if (change.firstChange) {
        console.log('✨ Initial value set!');
      } else {
        console.log('🔄 Value updated!');
      }
    }
  }
}

⚠️ IMPORTANT - OBJECT/ARRAY REFERENCE:

TypeScript (Parent):
export class AppComponent {
  // SCENARIO 1: Reference change (DETECTED ✅)
  userData = { name: 'Rahul', age: 24 };
  
  changeReference() {
    this.userData = { name: 'Priya', age: 26 };
    // New object reference → ngOnChanges TRIGGERS! ✅
  }
  
  // SCENARIO 2: Content change (NOT DETECTED ❌)
  changeContent() {
    this.userData.name = 'Amit';
    // Same object reference → ngOnChanges NOT TRIGGERED! ❌
    // Use ngDoCheck() for this!
  }
}

🔥 PRO TIPS:

✅ @Input() changes track karne ke liye perfect
✅ SimpleChanges mein previousValue aur currentValue milta hai
✅ firstChange property se pata chalega initial set hai ya update
✅ Multiple @Input() properties ek saath check kar sakte ho
✅ Validation logic yahan laga sakte ho

❌ COMMON MISTAKES:

export class AppComponent {

  updateName() {
    this.userData.name = 'Priya';  // Content change
  }

  }

CHILD:
export class UserComponent implements DoCheck {
  @Input() userData: any;
  private previousName: string = '';
  
  ngDoCheck() {
    // Custom logic to detect deep changes
    if (this.userData && this.userData.name !== this.previousName) {
      console.log(`🔍 Name changed: ${this.previousName} → ${this.userData.name}`);
      this.previousName = this.userData.name;
      
      // Update UI or perform actions
      this.onNameChange();
    }
  }
  
  onNameChange() {
    console.log('Handling name change...');
  }
}

⚠️ IMPORTANT RULES:

1️⃣ NEVER use ngOnChanges() aur ngDoCheck() together!
2️⃣ Keep logic simple - runs VERY frequently!
3️⃣ Performance impact ho sakta hai
4️⃣ Comparison logic efficient honi chahiye

🔥 PRO TIP: Most cases mein ngDoCheck() ki zarurat NAHI hoti!
Better: Object reference change karo → ngOnChanges() use karo

💡 EXAMPLE 1: Unsubscribe from Observables (MUST DO!)

TypeScript:
import { Component, OnInit, OnDestroy } from '@angular/core';
import { Subscription, interval } from 'rxjs';

@Component({
  selector: 'app-timer',
  template: `
    <div class="timer">
      <h2>Timer: {{seconds}} seconds</h2>
      <p>Component will cleanup on destroy ✅</p>
    </div>

})
export class TimerComponent implements OnInit, OnDestroy {
  seconds: number = 0;
  private timerSubscription!: Subscription;
  
  ngOnInit() {
    console.log('✅ Timer started');
    
    // Start interval
    this.timerSubscription = interval(1000).subscribe(() => {
      this.seconds++;
      console.log('Tick:', this.seconds);
    });
  }
  
  ngOnDestroy() {
    console.log('🧹 ngOnDestroy: Cleaning up...');
    
    // ⚠️ IMPORTANT: Unsubscribe to prevent memory leak!
    if (this.timerSubscription) {
      this.timerSubscription.unsubscribe();
      console.log('✅ Timer subscription unsubscribed');
    }
    
    // Clear any other resources
    console.log('✅ Component destroyed safely');
  }
}

💡 EXAMPLE 2: Multiple Subscriptions Cleanup

TypeScript:
import { Component, OnInit, OnDestroy } from '@angular/core';
import { Subscription } from 'rxjs';

@Component({
  selector: 'app-dashboard',
  template: `<div>Dashboard with multiple data streams</div>`
})
export class DashboardComponent implements OnInit, OnDestroy {
  private subscriptions = new Subscription();  // Container for all subscriptions
  
  userData: any;
  notifications: any[] = [];
  liveData: any;
  
  constructor(
    private userService: UserService,
    private notificationService: NotificationService,
    private liveDataService: LiveDataService
  ) {}
  
  ngOnInit() {
    // Add all subscriptions to container
    this.subscriptions.add(
      this.userService.getUser().subscribe(data => {
        this.userData = data;
      })
    );
    
    this.subscriptions.add(
      this.notificationService.getNotifications().subscribe(data => {
        this.notifications = data;
      })
    );
    
    this.subscriptions.add(
      this.liveDataService.getLiveData().subscribe(data => {
        this.liveData = data;
      })
    );
  }
  
  ngOnDestroy() {
    // ✅ Unsubscribe from ALL at once!
    this.subscriptions.unsubscribe();
    console.log('✅ All subscriptions cleaned up!');
  }
}

💡 EXAMPLE 3: Clear Timers and Event Listeners

TypeScript:
export class CountdownComponent implements OnInit, OnDestroy {
  countdown: number = 60;
  private intervalId: any;
  private clickListener: any;
  
  ngOnInit() {
    // Start countdown
    this.intervalId = setInterval(() => {
      this.countdown--;
      if (this.countdown <= 0) {
        this.onCountdownComplete();
      }
    }, 1000);
    
    // Add global event listener
    this.clickListener = this.handleGlobalClick.bind(this);
    document.addEventListener('click', this.clickListener);
  }
  
  ngOnDestroy() {
    console.log('🧹 Cleaning up countdown component...');
    
    // Clear interval
    if (this.intervalId) {
      clearInterval(this.intervalId);
      console.log('✅ Interval cleared');
    }
    
    // Remove event listener
    if (this.clickListener) {
      document.removeEventListener('click', this.clickListener);
      console.log('✅ Event listener removed');
    }
  }
  
  handleGlobalClick(event: MouseEvent) {
    console.log('Global click detected');
  }
  
  onCountdownComplete() {
    console.log('Countdown finished!');
  }
}

✅ Event listeners remove karo
✅ WebSocket connections close karo
✅ Third-party library cleanup karo
✅ LocalStorage / SessionStorage save karo (if needed)
✅ Custom cleanup logic

❌ MEMORY LEAK HOGA AGAR:
- Subscriptions unsubscribe nahi kiye
- Timers clear nahi kiye
- Event listeners remove nahi kiye
- WebSocket connections open chhod diye

🔥 PRO TIPS:

✅ ALWAYS unsubscribe in ngOnDestroy()
✅ Use Subscription container for multiple subscriptions
✅ HttpClient requests auto-unsubscribe (but best practice = manual)
✅ Async pipe automatically handles subscriptions
✅ RxJS operators like takeUntil() for auto-cleanup

  standalone: true

export class KeyboardShortcutsDirective {
  @HostListener('document:keydown', ['$event'])
  handleKeyboardEvent(event: KeyboardEvent) {
    // Ctrl + S → Save
    if (event.ctrlKey && event.key === 's') {
      event.preventDefault();
      console.log('💾 Save shortcut pressed (Ctrl+S)');
      this.save();
    }
    
    // Ctrl + P → Print
    if (event.ctrlKey && event.key === 'p') {
      event.preventDefault();
      console.log('🖨️ Print shortcut pressed (Ctrl+P)');
      this.print();
    }
    
    // Escape → Close
    if (event.key === 'Escape') {
      console.log('❌ Escape pressed - Close modal');
      this.closeModal();
    }
    
    // Ctrl + Z → Undo
    if (event.ctrlKey && event.key === 'z') {
      event.preventDefault();
      console.log('↩️ Undo shortcut pressed (Ctrl+Z)');
      this.undo();
    }
  }
  
  save() {
    alert('Saving document...');
  }
  
  print() {
    alert('Opening print dialog...');
  }
  
  closeModal() {
    alert('Closing modal...');
  }
  
  undo() {
    alert('Undoing last action...');
  }
}

Note: two types of pipe pure and impure pipe
1: pure pipe - it process input and return values without side effects, it only 
call when input change
2: impure pipe - it transform the data even input data hasnt change, it call twice
once when input changed and second for updating the view 
we will ad pure = false in @pipe decorator to make pipe impure by default it set to

import { AbstractControl, ValidationErrors } from "@angular/forms";

export function upperCaseValidator(control: AbstractControl): ValidationErrors | null {
    let userName: string = control.value as string;
    if (userName !== userName.toUpperCase()) {
        control.setValue(userName.toUpperCase());
    }
    return null
}

import { PreloadingStrategy, Route } from "@angular/router";
import { EMPTY, Observable } from "rxjs";

@Injectable({
    providedIn:'root'
})
export class customPreloading implements PreloadingStrategy{

       preload(route: Route, fn: () => Observable<any>): Observable<any> {

            return fn();

        console.log(route.path,'not preloaded'); 
        return EMPTY;

}
